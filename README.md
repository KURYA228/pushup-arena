# Push Up Legends

**Играть: https://pushuplegends.website.yandexcloud.net/** — открыть в Safari и добавить на экран «Домой». Работает и на мобильной связи в России (см. «Игра на Yandex Cloud»).

PWA-счётчик отжиманий для себя (репозиторий открыт, потому что GitHub Pages на бесплатном тарифе раздаёт только из публичных): боссы с HP, XP/уровни/ранги, стрики, достижения и режим Speed Rush. Повторы считает камера с помощью MediaPipe Pose (по углу локтя), с калибровкой и наложением скелета. Весь прогресс хранится локально в IndexedDB — бэкенда нет.

## Стек

- Vite + React + TypeScript
- Tailwind CSS 4
- PWA (`vite-plugin-pwa`) — устанавливается на телефон, работает офлайн
- IndexedDB через `dexie` / `dexie-react-hooks`
- `@mediapipe/tasks-vision` (PoseLandmarker) для AI-подсчёта повторов через камеру

## Запуск локально

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173/pushup-arena/` — подпапка в адресе появляется из-за `base`, настроенного под GitHub Pages (см. «Про базовый путь»). Камера работает только по `https://` или на `localhost` — это ограничение браузера, не приложения.

Проверить типы, линт и тесты:

```bash
npm run build   # tsc -b && vite build — попутно проверяет типы
npm run lint    # oxlint
npm test        # логика подсчёта повторов, node:test без доп. зависимостей
```

Тесты запускаются нативным раннером Node (нужен Node 22.6+ — TypeScript исполняется напрямую), поэтому в проекте нет ни vitest, ни jest.

## Сборка PWA

```bash
npm run build
npm run preview   # локально проверить прод-сборку
```

Результат — папка `dist/`, полностью статичная (можно раздавать откуда угодно: Nginx, Vercel, Netlify, GitHub Pages и т.д.). Сервис-воркер кеширует шелл приложения (JS/CSS/HTML/иконки), поэтому после первого визита UI и вся игровая логика работают офлайн. Прогресс (XP, боссы, достижения) хранится в IndexedDB и переживает офлайн-режим и перезапуск браузера.

### Как работает AI-подсчёт

Повтор определяется по углу локтя (плечо → локоть → запястье), но с двумя принципиальными оговорками.

**Угол считается в 3D, а не по картинке.** Берутся `worldLandmarks` — метрические координаты MediaPipe в метрах, а не нормализованные экранные `landmarks`. Экранные `x` и `y` нормированы независимо (по ширине и по высоте кадра), поэтому при кадре 4:3 угол в них искажён; и главное — при фронтальной камере сгибание локтя происходит вдоль оси обзора и на плоской проекции почти не видно. Третья координата снимает обе проблемы.

**Пороги подстраиваются под тебя.** Фиксированных «ниже 90° и выше 160°» нет: у разных людей отжимание укладывается в разные участки диапазона (кто-то 95°→160°, кто-то 115°→148°), и положение камеры сдвигает эти числа дальше. Детектор ведёт скользящее окно на 12 секунд, берёт 5-й и 95-й перцентили как твои личные «низ» и «верх» и ставит пороги в долях от этого размаха. Настраивается за пару повторов; пока не настроился — работает по нарочито мягким запасным порогам, чтобы первые повторы не потерялись. Выученный диапазон переживает отдых между подходами, иначе первый повтор каждого подхода терялся бы заново.

**Угол локтя сам по себе не отличает отжимание от жеста.** Согнуть локоть стоя — поднять руку, показать лайк, сделать подъём на бицепс — даёт ровно такой же график угла, как повтор. Отличается то, что делает остальное тело: **при отжимании кисти прибиты к полу и едет корпус, при жесте наоборот — плечо стоит, а запястье летает.** Детектор сравнивает, насколько за последнюю секунду сместились плечо и запястье (в длинах корпуса, чтобы не зависеть от расстояния до камеры), и считает повторы только когда плечо уверенно обгоняет запястье. Вердикт держится пару секунд, чтобы пауза в верхней точке не сбрасывала подход. Пока признак не выполнен, кадры не идут ни в счётчик, ни в оценку диапазона — иначе размах жеста растянул бы пороги так, что настоящие отжимания перестали бы засчитываться.

Сверху: медианный фильтр + сглаживание против дрожания модели, порог видимости суставов, усреднение по обеим рукам, минимальная задержка в нижней точке и минимальный интервал между повторами, прогрев фильтра (битый первый кадр не открывает фантомный цикл), а также требование минимального размаха в 30° — мелкие покачивания руками не засчитываются.

В настройках распознавания есть строгость (**Мягко / Обычно / Строго** — на какую долю диапазона надо опуститься), выбор модели (**Быстрая** `lite` / **Точная** `full`) и переключение фронтальной и основной камеры. Настройки хранятся в `localStorage`.

Вся эта логика лежит в `src/lib/repDetector.ts` — без React и без MediaPipe, на вход поток `(угол + позиции плеча и запястья, время)`. Поэтому она покрыта тестами: `npm test` прогоняет синтетические отжимания с разными диапазонами, темпом и шумом и проверяет, что ложных повторов не дают ни покой, ни дрожание на пороге, ни потеря трекинга, ни жесты рукой.

### Защита от видео вместо себя

Направить камеру на чужое видео с отжиманиями — проверки детектора это проходит: отжимания ведь настоящие, просто не твои. Надёжно отличить экран от живого человека по картинке нельзя, поэтому игра просит то, чего запись знать не может (`src/lib/liveness.ts`, тесты рядом):

- **Команды в случайный момент.** Первая — после 5–12 засчитанных повторов, дальше раз в 10–20. По очереди, с первой случайной: «Подними руку!» (рука выпрямлена и поднята до уровня плеча или выше, держать 0,4 с — дно глубокого отжимания так не выглядит, там локоть согнут) и «Замри наверху!» (руки прямые, ≥140°, 2 секунды без движения). Команда звучит голосом (русский голос `speechSynthesis`, два сигнала перед ним) и висит крупной плашкой вверху экрана с отсчётом. На выполнение 5–6,5 секунды.
- **Пока команда не выполнена, повторы не считаются.** Не успел — «Не успел», через 1,5 с новая команда, и так до прохождения. Уже засчитанные до команды повторы не отнимаются (они уже ударили по боссу), но видео набирает максимум несколько повторов и встаёт.
- **Косвенные признаки экрана** (`screenHints` в `usePoseDetection.ts`, раз в 0,5 с): всё тело меньше трети кадра по обеим осям, или область вокруг тела в 2,2+ раза ярче тёмных краёв кадра (светящийся прямоугольник в тёмной комнате). Три секунды подряд — и команды до конца сессии идут чаще: первая через 2–5 повторов, дальше раз в 3–6. Сами по себе признаки ничего не блокируют: они срабатывают и на честных игроках (далеко от телефона, яркое окно), а ложное обвинение хуже чужого счёта.

Проверка одна на страницу, а не на экран: переключение «Вручную ↔ Камера» и уход из боя её не сбрасывают.

### Надёжность камеры

- **Надёжность камеры** (`src/lib/camera.ts`, тесты рядом). Камера открывается с повторами: «занята» сразу после перезапуска или переворота (`NotReadableError`/`AbortError`) — ждём и пробуем снова до 3 раз; не умеет запрошенное разрешение (`OverconstrainedError`) — просим без требований к размеру; нет камеры с этой стороны (`NotFoundError`) — берём любую. Запрет доступа не повторяется, чтобы не донимать. Запуск видео тоже с повтором (iOS прерывает `play()` при смене потока). Движок грузится с jsDelivr, а если он недоступен — с unpkg. Если точная модель идёт медленнее 12 кадров/с три секунды подряд, камера сама переключается на быструю и говорит об этом. Пропорции кадра обновляются при повороте телефона. Непредвиденная ошибка показывается с её кодом.
- **Версия движка.** WASM MediaPipe грузится с CDN той же версии, что и установленный пакет `@mediapipe/tasks-vision` — версия подставляется при сборке (`__MEDIAPIPE_VERSION__` в `vite.config.ts`). Раньше она была зашита отдельно и отстала на два мажорных релиза.
- **Тайм-аут загрузки модели** — 60 с, дальше понятная ошибка и «Повторить попытку» вместо вечного «Загружаем модель…».
- **Возврат в приложение.** iOS при сворачивании или блокировке экрана ставит видео на паузу или вовсе завершает дорожку камеры, и счётчик замирал, ничего не считая. Теперь при возврате пауза снимается, а мёртвая камера открывается заново.
- **Сторож зависшего видео.** Нет новых кадров 2,5 с — видео снова запускается; 6 с — камера переоткрывается целиком. Перезапуски не чаще раза в 4 секунды.
- **Камеру забрали** (звонок, другое приложение) — по событию `ended` камера переоткрывается.
- **Сломался движок** (обычно — потерянный GPU-контекст): 20 неудачных кадров подряд — перезапуск на CPU, дальше в этой сессии только CPU.
- **Нет API камеры** (встроенные браузеры Telegram/Instagram, http) — сообщение «открой в Safari или Chrome» вместо невнятной ошибки.
- **Камера «в лоб».** Спереди сгиб локтя идёт вдоль линии взгляда, и даже полное отжимание даёт размах 15–25° — меньше 30°, нужных для калибровки, поэтому счёт молча не начинался. Детектор теперь следит за видимым размахом (`observedSpread`), и если движение есть, а размах мал, подсказка просит поставить телефон сбоку (`cameraLooksHeadOn`).
- **Только отжимания.** Повтор считается, только если корпус в упоре лёжа: наклон линии «плечи → бёдра» от горизонтали по 3D-координатам (`torsoTilt` в `usePoseDetection.ts`) не больше 50°. На реальных снимках упор лёжа даёт 25–30°, стоящий человек — около 80°. Сидя или стоя перед телефоном можно махать руками сколько угодно — не засчитается, и подсказка скажет «прими упор лёжа»; если бёдер не видно — «отодвинь телефон». Короткая потеря бёдер внизу повтора (до секунды) счёт не ломает. Заодно исправлена нормировка в тесте «двигается корпус, а не рука»: расстояния делились на длину руки в каждом кадре, а у руки, направленной в камеру, она резко сокращается — и неподвижное плечо «ездило» по кадру. Теперь делится на наибольший размер тела за окно.
- **Компактная камера и без «+».** В режиме камеры вместо большого окна — миниатюра со скелетом и шкалой глубины, а рядом подсказка, «−1», «Калибровка» и переключение камеры: босс, его HP и урон остаются на экране целиком, пока ты лежишь на полу. Кнопка «Крупнее» рядом с миниатюрой (или тап по самой миниатюре) раскрывает камеру во всю ширину, чтобы выставить телефон; «Свернуть» — обратно (это тот же `<video>`, поток не прерывается). Кнопки «+» в режиме камеры нет: считает камера, а кнопка рядом только провоцирует тыкать вместо отжиманий; «−1» остаётся — снять ошибочно засчитанный повтор.
- **Дублёр.** В свёрнутой камере рядом живёт легионер из справки (`PushupGuy` в режиме `follow`): пока камера тебя видит в упоре лёжа, он отжимается, а на каждом засчитанном повторе над ним всплывает «+1» и реплика («уф!», «красава», «босс плачет»…). Пока тебя не видно, он спит на спине, и из шлема поднимаются «z», которые растут по пути и исчезают на самом крупном размере. Заодно это второй способ увидеть, что камера действительно за тобой следит.
- **Режим «Камера» запоминается** (`arena.counterMode`), не нужно включать его заново на каждом экране боя и в каждом забеге Rush.

### Офлайн и модели

Модель распознавания позы (`pose_landmarker_lite.task` ~5 МБ или `pose_landmarker_full.task` ~9 МБ) и wasm-рантайм MediaPipe грузятся с CDN (`storage.googleapis.com` / `cdn.jsdelivr.net`) при **первом** использовании камеры. После первого запуска браузер кеширует их через `runtimeCaching` в service worker (CacheFirst, на 90 дней), так что дальше камера будет работать и без сети. Ручной режим (+1/−1) и вся остальная игра офлайн-доступны сразу, без единого захода в сеть. Переключение модели в настройках скачивает вторую — тоже один раз.

Если хочешь полный офлайн с первого запуска — скачай файлы сам и положи их в `public/mediapipe/`:
- `https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task`
- `https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/1/pose_landmarker_full.task`
- wasm-рантайм из `@mediapipe/tasks-vision/wasm/*` (уже есть в `node_modules` после `npm install`, можно скопировать)

и поменяй константы `WASM_BASE` / `MODEL_URLS` в `src/hooks/usePoseDetection.ts` на локальные пути (`/mediapipe/...`).

## Деплой

Приложение живёт на GitHub Pages: **https://kurya228.github.io/pushup-arena/**

HTTPS есть, значит камера работает; на телефоне можно поставить на домашний экран и пользоваться офлайн. Дев-сервер для этого больше не нужен.

Выкатить новую версию:

```bash
npm run deploy
```

Скрипт прогоняет линт и тесты, собирает и force-пушит `dist/` в ветку `gh-pages`, откуда Pages и раздаёт. Ветка содержит только результат сборки, её история одноразовая.

### Про базовый путь

Pages отдаёт приложение из `/pushup-arena/`, а не из корня домена. Поэтому в `vite.config.ts` задан `base`, а `start_url`, `scope`, иконки манифеста и `navigateFallback` собраны от него же. Иконки боссов хранятся в данных **именами файлов**, а не путями, и склеиваются с `import.meta.env.BASE_URL` в `BossIcon` — абсолютный `/bosses/...` отвалился бы на любом хостинге с подпапкой.

Если будешь разворачивать туда, где приложение лежит в корне (Vercel, Netlify), собери с `BASE_PATH=/`:

```bash
BASE_PATH=/ npm run build
```

### Автодеплой при пуше

Сейчас его нет: у локального токена `gh` нет права `workflow`, поэтому файл workflow не проходит в репозиторий. Готовый лежит в `scripts/github-pages-workflow.yml`. Чтобы включить автосборку при каждом пуше в `main`:

```bash
gh auth refresh -s workflow
```

затем перенести файл в `.github/workflows/deploy.yml`, запушить и в настройках репозитория переключить источник Pages с ветки на GitHub Actions. После этого `npm run deploy` больше не нужен.

## Аккаунты и таблица лидеров

По умолчанию их нет и приложение полностью автономно. Чтобы включить, нужен бесплатный проект Supabase — GitHub Pages умеет только отдавать файлы, своего кода на сервере у нас нет.

1. Завести проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватит с запасом).
2. **SQL Editor → New query** → вставить целиком `supabase/schema.sql` → Run.
3. **Authentication → Providers → Email**: выключить «Confirm email», иначе после регистрации придётся идти в почту.
4. **Project Settings → API**: скопировать Project URL и ключ `anon public`.
5. Создать в корне проекта файл `.env.local` по образцу `.env.example`:

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGci...
   ```

6. Перезапустить `npm run dev`. Для выкатки на Pages значения нужно подставить и при сборке.

Ключ `anon` **публичный по замыслу** — он уезжает в браузер вместе со страницей и идентифицирует проект, а не человека. Данные защищает row-level security из `schema.sql`: без этих политик ключ и правда был бы открытой дверью. `.env.local` в репозиторий не попадает, но не потому что ключ секретный, а чтобы у каждого был свой проект.

### Как устроено

Игра остаётся **offline-first**: IndexedDB — по-прежнему источник правды, облако лишь зеркало. Отправка идёт с задержкой в 4 секунды после последнего изменения (подход — это сорок повторов за минуту, и ни сеть, ни человек не должны этого чувствовать) и молча переживает отсутствие связи. Без входа и без ключей работает ровно то же, что и раньше.

**Аккаунт означает один результат на всех устройствах.** Долгое время загрузка вниз была только кнопкой — она может затереть местный прогресс. Но из-за этого телефон и ноутбук под одной почтой считали каждый своё, а в таблицу попадал тот, кто отправил последним.

Теперь обе стороны сводятся автоматически, но только там, где это доказуемо ничего не стоит. Помогает третья точка отсчёта — **метка синхронизации** (`src/lib/syncMark.ts`): отпечаток прогресса на момент последнего согласия с сервером. Она лежит на устройстве, потому что описывает состояние устройства, а не аккаунта.

С ней разбирается любой случай:

| местное | облако | что делаем |
|---|---|---|
| = метке | ≠ метке | устройство просто отстало → забираем облачное, терять нечего |
| ≠ метке | = метке | устройство впереди → обычная отправка наверх |
| ≠ метке | ≠ метке | оба ушли вперёд → **спрашиваем**, сами не решаем |
| совпадают | | ничего не делаем |

Сводится при появлении сессии и при каждом возврате в приложение — телефон, который неделю не перезагружали, иначе никогда бы не проверился. Если метки нет вообще (свежая установка, очищенное хранилище), это считается расхождением: без предка нельзя отличить новую работу от остатков, а угадывать здесь — значит однажды стереть чей-то подход.

При расхождении на вкладке «Лидеры» появляется карточка с обеими цифрами и двумя кнопками. Автоматического слияния нет и не будет: прогресс по боссам — не число, которое можно сложить.

Логика сверки — чистая функция и покрыта тестами поштучно, включая случай «отстал, но с бо́льшим числом»: отмена повтора на другом устройстве законно уменьшает счёт, и за ней надо следовать вниз.

Отправка наверх **не даёт зачёту падать**: в публичную строку пишется максимум из своего и уже записанного, а сохранёнку отставшее устройство вообще не публикует — иначе кнопка «загрузить с другого устройства» однажды вернула бы версию поменьше. Исключение одно: выбор, который человек сделал руками в карточке расхождения. Стрик из максимума исключён — порванный стрик законно падает до единицы, и максимум заморозил бы враньё навсегда; он берётся с той копии, которая дальше по общему счёту.

Сама таблица сортируется четырьмя способами — отжимания, уровень, боссы, рекорд Rush, — и это не украшение: одна цифра свела бы игру к «кто больше отжался», а так первым можно стать по-разному. Верхняя тройка выносится на подиум, остальные идут списком. Стрелки роста и падения считаются от того, как таблица выглядела в прошлый твой заход: прошлые места лежат в `localStorage` (`arena.lastRanks`), потому что «с прошлого раза» — понятие устройства, а не сервера.

**Устройство запоминается.** Токен сессии живёт в `localStorage` под ключом `arena.auth` и обновляется сам, так что вход переживает перезапуск приложения — пароль спрашивают один раз. Переключатель «Запомнить это устройство» переносит токен в `sessionStorage`: тогда выход происходит при закрытии вкладки. Переключение действует сразу, а не со следующего обновления токена, — на чужом телефоне это важно.

Рядом с токеном лежит `arena.lastAccount` (адрес и имя), поэтому вошедший однажды видит не форму, а приветствие с одним полем пароля. «Это не я» и «Забыть» стирают эту запись.

Ключ хранения задан явно (`arena.auth`) вместо дефолтного `sb-<ref>-auth-token`: при первом запуске старое значение переносится один раз, иначе обновление выкинуло бы всех вошедших на форму входа.

**Пропавшая связь — не выход из аккаунта.** `getSession()` отвечает `null` в двух разных случаях: никто не входил, и войти-то входили, но обновить токен не вышло из-за сети. Раньше приложение считало это одним и тем же и показывало форму входа человеку, который из аккаунта не выходил. Теперь `hasStoredSession()` смотрит, лежит ли в хранилище refresh-токен, и при живом токене вместо формы появляется экран «Сервер не отвечает» с кнопкой «Повторить». Возврат сети ловится событием `online`, так что обычно жать ничего не нужно. Ждём ответа сервера не дольше трёх секунд: Supabase перебирает попытки с нарастающей паузой и сдаётся секунд через тринадцать — слишком долго, когда ответ уже лежит на устройстве.

При входе вызывается `navigator.storage.persist()`. Это касается не только сессии: вся игра лежит в IndexedDB, а Safari выбрасывает хранилище сайтов, которые не открывали неделю. Установленному PWA разрешение выдаётся молча, обычной вкладке могут и отказать — поэтому результат ни на что не влияет, это просьба, а не гарантия.

Таблицы две, и это принципиально. `players` — публичные имя и цифры, их видят все вошедшие. `saves` — полная выгрузка профиля, доступна только владельцу. В одной таблице политика, открывающая таблицу лидеров, открыла бы заодно и сохранёнку.

### Чего эта схема не может

**Накрутку не остановить.** Повторы считаются на устройстве, и любой может записать себе любое число — хоть через консоль, хоть через встроенную дев-панель. Технической защиты тут нет и быть не может, пока считает клиент; таблица держится на том, что играющие друг друга знают.

### Обнулить прогресс всех игроков

Нужно, когда игра выходит из тестирования: люди уже успели набить отжимания и уровни, и на старте все должны быть на нуле.

**Стереть строки в Supabase недостаточно.** Настоящее сохранение каждого игрока лежит у него в браузере, в IndexedDB; облако — только зеркало. Если просто очистить таблицы, то при следующем запуске игры устройство увидит, что аккаунт отстал, и зальёт свой прогресс обратно. А тех, кто вообще не заходил, это и не коснётся.

Поэтому сбросом управляет число `SEASON` в `src/lib/season.ts`. Оно едет внутри самого приложения, а значит доходит до всех: и до тех, кто играет без аккаунта, и до тех, кто офлайн, и до установленных на телефон копий. Каждое сохранение помнит свой сезон, и сохранение из прошлого выбрасывается — и на устройстве, и в облаке.

Порядок важен:

1. Поднять `SEASON` на единицу в `src/lib/season.ts` и подписать в комментарии, что это за прогон.
2. `npm run deploy` — с этого момента каждое устройство, открывшее игру, само стирает свой старый профиль.
3. Выполнить `supabase/reset-season.sql` в Supabase → SQL Editor. Это обнуляет таблицу лидеров сразу, не дожидаясь, пока каждый зайдёт.

Если сделать наоборот — сначала SQL, потом деплой, — то устройство со старой версией успеет залить прогресс обратно, и придётся выполнять SQL второй раз.

Аккаунты, почты и пароли не трогаются: люди остаются зарегистрированными, имена в таблице лидеров сохраняются, обнуляется только прогресс. В том же SQL-файле лежат закомментированные варианты: обнулить одного игрока по имени и удалить аккаунт целиком.

Сброс необратим. Выгрузить всё перед ним — `select * from public.saves;` в SQL Editor, кнопка «Download CSV».


### Вход через Google

На экране входа под «Создать аккаунт» / «Войти» есть кнопка «Зарегистрироваться через Google» / «Войти через Google» (`signInWithGoogle` в `src/lib/cloud.ts`): уводит на Google и возвращает в игру уже вошедшим. Регистрация и вход — один и тот же шаг. Если у аккаунта ещё нет имени в таблице, игра сама попросит его выбрать — с ником из интро в поле.

Один раз нужно включить в настройках:

1. **Google Cloud Console** (console.cloud.google.com) → APIs & Services → **OAuth consent screen**: тип External, название приложения, почта поддержки → сохранить (и «Publish app», чтобы входить мог любой, а не только тестовые адреса).
2. Там же **Credentials → Create credentials → OAuth client ID** → тип **Web application** → в **Authorized redirect URIs** добавить `https://<проект>.supabase.co/auth/v1/callback` (адрес проекта — `VITE_SUPABASE_URL` из `.env.local`) → Create. Скопировать **Client ID** и **Client secret**.
3. **Supabase → Authentication → Sign In / Providers → Google**: включить, вставить Client ID и Client secret, сохранить.
4. **Supabase → Authentication → URL Configuration → Redirect URLs**: должны быть адреса игры **со звёздочками на конце** — `https://kurya228.github.io/pushup-arena/**` и для разработки `http://localhost:5173/pushup-arena/**`. Звёздочки обязательны для входа с экрана «Домой» на iPhone: туда Google возвращает с `?handoff=…` в адресе, и без них Supabase молча отправит на Site URL.
5. **Supabase → SQL Editor**: запустить `supabase/handoff.sql` (нужен для iPhone, см. ниже).

Пока Google не включён, кнопка уведёт на страницу Supabase с ошибкой «provider is not enabled».

**iPhone, игра на экране «Домой».** Установленная игра на iOS живёт отдельно от Safari, с собственным хранилищем. Google открывается в окне Safari поверх игры и туда же возвращается — раньше вход оседал в этом окне, а игра оставалась на форме. Теперь в этом случае (iOS + standalone) вход идёт по PKCE: игра держит у себя секрет (code verifier) и отправляет на Google со случайным ключом `?handoff=<nonce>`. Окно Safari, вернувшись, не запускает игру, а показывает «Вход выполнен» (`HandoffRelay`) и кладёт одноразовый код в таблицу `auth_handoff` (`supabase/handoff.sql`, функции `handoff_put` / `handoff_take`). Игра раз в 2,5 секунды и при возвращении на экран спрашивает свой ключ, забирает код, обменивает его на сессию и передаёт основному клиенту (`watchHandoff` в `src/lib/cloud.ts`). Код без секрета бесполезен, а секрет из игры не уходит. Если iOS всё-таки вернёт прямо в игру — она обменяет код сама, без таблицы. В обычной вкладке Safari и на Android вход работает по-старому.

### Игра на Yandex Cloud

На мобильной связи в России режут и `github.io`, поэтому основная ссылка на игру — **https://pushuplegends.website.yandexcloud.net/** (Yandex Object Storage, бакет `pushuplegends`, хостинг сайта: главная и страница ошибки — `index.html`, «Чтение объектов — Для всех»). GitHub Pages остаётся как запасной адрес.

`npm run deploy` после GitHub собирает игру ещё раз с `BASE_PATH=/` и заливает её в бакет (`scripts/upload-yandex.mjs`): хэшированные файлы из `assets/` — с вечным кэшем, всё остальное (`index.html`, `sw.js`, манифест) — с `no-cache`, чтобы телефоны подхватывали новую версию. Ключ — статический ключ сервисного аккаунта `arena-deploy` (роль `storage.editor`) в `.env.deploy.local`:

```
YC_ACCESS_KEY_ID=…
YC_SECRET_ACCESS_KEY=…
```

Файл в `.gitignore`. Без ключа шаг Яндекса пропускается. Другой бакет — `YC_BUCKET=имя npm run deploy`.

В **Supabase → Authentication → URL Configuration → Redirect URLs** должен быть `https://pushuplegends.website.yandexcloud.net/**` — иначе вход через Google и ссылки подтверждения почты вернут на GitHub-адрес.

У игры на новом адресе своё хранилище: прогресс приезжает из облака после входа в аккаунт.

### Прокси через Yandex Cloud

Мобильные операторы в России режут `*.supabase.co`: на Wi‑Fi вход работал, а на мобильной связи игра с экрана «Домой» писала «Нет связи с сервером» (обычный Safari при этом мог проходить через Частный узел iCloud и не замечать блокировки). Поэтому все запросы игры идут через **Yandex Cloud API Gateway** `arena-proxy` — шлюз в России, который пересылает их в Supabase как есть. Адрес шлюза — `VITE_SUPABASE_PROXY_URL` в `.env.local`; без него игра ходит в Supabase напрямую, как раньше. `VITE_SUPABASE_URL` остаётся настоящим адресом проекта: по нему же старые фото-аватарки переписываются на шлюз (`avatarSrc`).

Спецификация шлюза (консоль Yandex Cloud → API Gateway → `arena-proxy` → Редактировать):

```yaml
openapi: 3.0.0
info:
  title: arena-proxy
  version: 1.0.0
paths:
  /{path+}:
    x-yc-apigateway-any-method:
      x-yc-apigateway-integration:
        type: http
        url: https://xhfhfdkqshyzffduiuzv.supabase.co/{path}
        headers:
          '*': '*'
          Host: xhfhfdkqshyzffduiuzv.supabase.co
        query:
          '*': '*'
        timeouts:
          connect: 5
          read: 30
      parameters:
        - name: path
          in: path
          required: false
          schema:
            type: string
```

Стоимость: первые 100 000 запросов и 100 ГБ трафика в месяц бесплатно, дальше 142,3 ₽ за миллион запросов. Не идут через шлюз только переходы, которые Supabase делает сам: последний шаг входа через Google (`supabase.co/auth/v1/callback`) и ссылки из писем подтверждения. Поэтому на мобильной связи надёжнее вход по почте.

### Нет связи с сервером («Load failed»)

`Load failed` — так Safari называет запрос, который вообще не ушёл с телефона. Если интернет есть, а вход и по почте, и через Google падает с этой ошибкой, почти всегда виноват **блокировщик контента** (AdGuard, 1Blocker, Wipr и т. п.): адрес, набранный руками, он пропускает — поэтому `https://<проект>.supabase.co/auth/v1/health` в Safari открывается и показывает `No API key found`, — а тот же запрос со страницы режет. Игра в этом случае пишет «Нет связи с сервером…» с подсказкой (`translate` в `src/lib/cloud.ts`), а в справке «Как играть» есть раздел «Не входит: «Нет связи с сервером»».

Что делать игроку:

1. Настройки → Приложения → Safari → Расширения (на старых iOS — Настройки → Safari → Блокировщики контента): выключить блокировщики или добавить в исключения `kurya228.github.io` и `supabase.co`.
2. VPN, AdGuard DNS, NextDNS — выключить на время или добавить те же исключения.
3. Не помогло — выключить Частный узел iCloud или сменить сеть (Wi‑Fi ↔ мобильный интернет).
4. Полностью закрыть игру и открыть заново.

После этого «Аккаунт уже существует» и «Неверная почта или пароль» — уже честные ответы сервера. Аккаунт, созданный через Google, пароля не имеет: в него входят только кнопкой «Войти через Google».

## Дев-панель

Отладочная панель в выложенной игре открывается **только админу** — вошедшему аккаунту из таблицы `admins` (см. «Админ-панель» ниже); как её открыть, знает владелец. Остальным скрытый вход ничего не даёт, даже если они его знают. При локальном запуске (`npm run dev`) рядом с заголовком есть кнопка **DEV**. Панель не вырезается из прод-сборки — проверять что-то удобнее на телефоне, где стоит собранная версия; закрывает её не секретность входа, а проверка админа в базе.

Что умеет: прыжок на любого из 12 боссов (все предыдущие при этом помечаются побеждёнными, чтобы состояние оставалось связным), «оставить 1 удар» для проверки победной анимации и тостов, переход на произвольный уровень, правка счётчиков (всего отжиманий, стрик, рекорд Rush), открыть/закрыть все достижения или каждое по отдельности, обнулить кольца (стереть из журнала отжимания за сегодня или за неделю — неделя заодно снимает отметку о выданной награде) и вернуть нормы к умолчанию и полный сброс профиля с подтверждением в два нажатия. Там же переключатель **кнопки «+»**: «Кликер» (по умолчанию) или «Отжимания» — во втором режиме «+» засчитывается как отжимание с камеры (урон, XP, общий счёт), чтобы проверять боссов и магазин без камеры. Флаг хранится в `localStorage` этого устройства (`src/lib/devFlags.ts`), в сейв и в облако не попадает; пока он включён, под кнопками висит красная пометка DEV. Блок **«Магазин»** сбрасывает купленные улучшения — просто так или с возвратом потраченного XP (сумма цен купленных уровней); заморозки стрика он не трогает, их число правится в «Счётчиках».

Записи идут через тот же Dexie-хендл, что и вся игра (`devPatchProfile` / `devResetProfile` в `useProfile`), поэтому UI обновляется сразу — правка IndexedDB в обход Dexie потребовала бы перезагрузки, `useLiveQuery` её не увидит.

Переход на уровень опирается на `totalXpForLevel` — точную инверсию `levelFromTotalXp`, потому что хранится именно XP, а уровень из него выводится. Инверсия покрыта тестами: без этого «перейти на 20-й» роняло бы на 19-й.

## Отклик на повтор и экран

Отжимаясь, ты лежишь лицом в пол, а телефон стоит сбоку — экрана не видно. Поэтому на каждый засчитанный повтор идёт короткий звук и вибрация. У победы над боссом фанфара из трёх нот, у нового уровня и конца Rush свои сигналы, а **критический урон звучит как хедшот из шутера**: запись `public/sfx/headshot.m4a` (оригинал — `art/sfx/headshot-original.mp3`), одна и та же на каждом крите — у босса, у подчинённых и в Rush. Играется с исходной высотой тона, без случайного разброса, как у монет и хрюка: в ней голос, а сдвиг высоты превращал бы его каждый раз в другого человека.

У некоторых боссов свой звук удара вместо обычного писка — только у самого босса, его подчинённые звучат обычно, чтобы особый звук отмечал выход босса (`hitSound` в `src/data/bosses.ts`): у Мистера Крабса сыплются монеты, у Короля Свина хрюк (записи в `public/sfx/`), у Шкипера шлепок ластой (синтезированный `flipperSlap`: свист воздуха и хлёсткий шлепок с низким ударом под ним), у Робина удар боевым шестом (синтезированный `staffStrike`: короткий свист замаха и сухой деревянный «тук» — щелчок и пара тонов, которые глохнут за сотые доли секунды, иначе дерево зазвенело бы как маримба), у Фредди гудок его носа, как на плакате из первой FNAF (синтезированный `noseHonk`: две чуть расстроенные пилы — дребезг резиновой груши — через полосовой фильтр, высота тона к концу проседает, как у кончающегося воздуха), у Джокера его шуточный электрошокер для рукопожатий (синтезированный `joyBuzzer`: искра и трескучее «бззт» — низкая прямоугольная волна, громкость которой рубит быстрый прямоугольный же генератор, плюс треск шума поверх), у Эндер-дракона майнкрафтовский «уф» получения урона (запись `public/sfx/hurt.m4a`, оригинал — `art/sfx/ender-hurt-original.mp3`), у Николь удар кошачьих когтей (синтезированный `clawSwipe`: широкий взмах лапы и поверх него три узких высоких «вжик» с разницей в доли секунды — по одному на коготь), у Грю выстрел замораживающего луча — синтезированный (`freezeRay` в `src/lib/feedback.ts`): лазерное «пиу» с падающей высотой, шипение намерзающего льда и стеклянный звон, всё короче четверти секунды и каждый раз чуть по-разному.

Звуки ударов — только звуковые эффекты, без голоса: удар звучит сотню раз за тренировку, и голос на нём быстро надоедает. Голос у босса другой — **реплика на выходе**: один раз, когда босс появляется на арене, после громкого «BOSS» (`line` в `src/data/bosses.ts`, файлы в `public/sfx/lines/`). Сейчас реплики есть у Мистера Крабса — «разочарованный» звук из «Губки Боба» (оригинал — `art/sfx/krabs-original.mp3`), у Робина — его песня из «Юных Титанов, вперёд!» целиком, 5,8 секунды: запись была заметно тише остальных, поэтому её громкость подтянута мягким лимитером до уровня других реплик (оригинал — `art/sfx/robin-original.mp3`), у Фредди — мем «Oh sh*t, is that Freddy Fazbear?» и начало его песенки, до естественной паузы на 6,6 секунды (оригинал — `art/sfx/freddy-original.mp3`; в начале английское ругательство), у Джокера — последние 4 секунды его смеха, самый мощный заход, который в конце сам затихает (оригинал — `art/sfx/joker-original.mp3`), у Эндер-дракона — звук нового уровня из Майнкрафта, обрезанный по концу звучания и чуть подтянутый по громкости (оригинал — `art/sfx/ender-original.mp3`), у Николь — первые 5 секунд темы «Удивительного мира Гамбола», так же обрезанные в паузе мелодии и приглушённые (оригинал — `art/sfx/nicole-original.mp3`), у Короля Свина — первые 3,7 секунды темы Angry Birds, обрезанные в паузе между фразами мелодии и плавно приглушённые (оригинал — `art/sfx/pig-original.mp3`), у Грю — «Minions! Tonight, we steal the moon!» с ликованием миньонов, которое плавно затухает к 8,6 секунде вместо того, чтобы оборваться (оригинал — `art/sfx/gru-original.mp3`), — и у Шкипера — мем «Los pingüinos me la van a mascar… Kawasaki, Cabo, Rico y Skipper» (оригинал — `art/sfx/penguins-original.mp3`; в игру идёт дорожка голоса, отделённая от фона нейросетью Demucs). Звучит только запись: если её нет, реплики просто нет — синтез речи не изображает персонажей. Пока босс говорит, он «говорит» и на экране: реплика идёт через измеритель громкости (`bossLineLevel` в `src/lib/feedback.ts`), и каждый кадр `BossTalk.tsx` двигает босса в такт громкости: на громких слогах он подпрыгивает, мультяшно вытягивается и раскачивается, за ним дышит большое сияние цвета этапа, на каждом новом слоге от него расходится кольцо-«звуковая волна», а у плеча с первого звука реплики висит комиксовый пузырь с прыгающим эквалайзером — он и сам пульсирует в такт голосу: раздувается, покачивается и светится цветом этапа на громких местах — и пропадает, как только реплика закончилась; в паузах всё затихает, после реплики босс плавно возвращается на место. Если файл реплики ещё грузится, когда босс выходит, она ждёт его (но не дольше чем на полсекунды позже положенного), и анимация ждёт вместе с ней. При системном «Уменьшить движение» анимации нет.

Пока запись не загрузилась (она начинает грузиться с первого касания экрана) или если браузер не смог её проиграть, вместо неё звучит прежний синтезированный сигнал: щелчок попадания из полосового шума, нисходящий свип для веса и голос встроенного синтеза речи (`speechSynthesis`), произносящий «Headshot». Для него явно выбирается английский голос (русский прочитал бы «Headshot» кириллицей), по возможности мужской и низкий, с `pitch 0.4` и `rate 0.9` под манеру арены. Перед каждой репликой вызывается `cancel()` — иначе на серии критов фразы копятся в очереди и диктор всё сильнее отстаёт от повторов. Список голосов и на iOS сам синтез разблокируются на первом касании экрана, там же, где и аудиоконтекст.

Если голосов в системе нет вообще, вместо реплики звучит металлический звон на негармонических обертонах (отношения 1 / 1.51 / 2.34 вместо целых) — целые кратные слышатся как музыкальная нота, нецелые как удар по металлу. Без всего этого камера вообще не даёт понять, засчитала она что-нибудь или нет.

Оба канала выключаются в «Настройках» (кнопка есть и в ручном режиме, не только в режиме камеры) и запоминаются в `localStorage`.

Что важно знать про ограничения платформ:

- **Вибрации на iPhone не будет.** Safari не реализует `navigator.vibrate` вообще. Переключатель в настройках это видит и подписывает «не поддерживается этим браузером». На iOS всю работу делает звук.
- **Звук на iOS подчиняется переключателю «Без звука» — если не включить «Даже в беззвучном режиме».** По умолчанию WebAudio идёт через звонковый канал, и в беззвучном режиме бипов нет. Переключатель в настройках боя (`loud` в `FeedbackPrefs`, `applyAudioSession` в `src/lib/feedback.ts`) ставит `navigator.audioSession.type = 'playback'` — так звучат видео и музыка, и беззвучный режим их не глушит. Работает в Safari с iOS 16.4; цена — такой звук может ставить на паузу музыку из других приложений, поэтому по умолчанию выключено.
- Аудиоконтекст создаётся при первом касании экрана, иначе браузер его не запустит: повтор от камеры — не жест пользователя, и первый подход остался бы немым.

Пока ты на экране боя или Speed Rush, приложение удерживает экран включённым через Wake Lock — иначе телефон блокируется примерно через полминуты и вместе с ним умирает поток с камеры. Блокировка автоматически перезапрашивается, когда возвращаешься во вкладку: браузер снимает её каждый раз, когда страница уходит из виду.

## Игровые механики

- **XP/уровни/ранги**: за повтор — XP (в боях с боссами больше, чем в Rush), бонус от стрика до +50%. Ранги: Новичок → Боец → Воин → Чемпион → Легенда → Титан → Полубог → Бессмертный.
- **Этапы**: 15 этапов, в каждом три подчинённых и потом босс — 60 противников на всю арену. HP подчинённых **вырезано из бюджета этапа**, а не добавлено сверху: арена осталась примерно на 3500 повторов, но побед в ней теперь вчетверо больше. Столько же работы, вчетверо чаще что-то умирает.
- **Ранги** (`src/data/ranks.ts`, карточка — `RanksCard.tsx`). Три лестницы, каждая про своё; награда — статус и косметика, бой они не меняют.
  - **Звание** — по уровню (Новичок → Боец → Воин → Чемпион → Легенда → Титан → Полубог → Бессмертный). У каждого значок и цвет: рамка аватара в таблице лидеров (с Легенды — светящаяся, у Бессмертного — корона), цвет имени, цвет цифр урона в бою.
  - **Лига недели** — по отжиманиям с понедельника: Бронза → Серебро (100) → Золото (250) → Платина (500) → Алмаз (800) → Мастер (1200), внутри каждой ступени III → II → I. В понедельник счёт с нуля.
  - **Сила** — по лучшему подходу без паузы (пауза от 3 секунд — новый подход): Крепыш 10 → Силач 20 → Атлет 30 → Богатырь 50 → Геркулес 75 → Колосс 100.

  Неделя, текущий подход и лучший подход считаются на каждом повторе (`advanceTraining` в `src/lib/training.ts`) и хранятся в профиле, поэтому уходят в облако и откатываются кнопкой «−1». Повышение на любой лестнице — экран-церемония (`RankUpOverlay.tsx`: лучи, значок, конфетти, фанфара `playRankUp`); счёт камеры под ним не останавливается. На главном — карточка «Ранги» с прогрессом до следующей ступени каждой лестницы; нажатие на плитку открывает окно со ступенями сразу на её вкладке (Звание · Лига недели · Сила). В таблице лидеров — рамки и цвета званий, значки лиги и силы у имён, вкладки «Лига» и «Подход». В дев-панели раздел «Ранги»: прыжок на любое звание, поля «отжиманий за неделю» и «лучший подход», кнопки, показывающие экран повышения каждой лестницы; раздел «Бой»: HP врага, сброс состояния способностей, «Разведку — заново», выход из реванша. Для них в Supabase нужны три колонки: **один раз запусти `supabase/ranks.sql`** в SQL Editor; до этого игра работает как раньше, просто без этих чисел в общей таблице.

- **Аватарки** (`src/lib/avatar.ts`, окно — `AvatarPicker.tsx`): в таблице лидеров нажми на свою аватарку в шапке — можно загрузить своё фото (обрезается по центру в квадрат 320×320 и сжимается в JPEG прямо на телефоне), вернуть букву имени или выбрать портрет с арены. Фото и буква доступны всегда, а портреты зарабатываются: босс — после победы над ним, подчинённый — как только он побеждён (или пройден весь его этап); считается по настоящему прогрессу, не по реваншу (`unlockedAvatars`). Закрытые показаны размытыми с замком и по нажатию говорят, кого победить. Выбор хранится в строке игрока (`players.avatar`: `g:<файл>` для портрета, адрес для фото), фото — в публичном хранилище `avatars`, у каждого своя папка, старое фото удаляется при загрузке нового. Нужны колонка и хранилище: **один раз запусти `supabase/avatars.sql`** в SQL Editor; до этого у всех буква, а окно выбора говорит, что скрипт не запущен.

- **Круги** (`hardenAbilities` в `src/data/abilities.ts`). Когда арена пройдена, кнопка «Пройти снова · Круг N» на итоговом экране запускает перепрохождение всей арены с усилением `replay.tier` (1 = Круг 2, до `MAX_TIER` = 4, Круг 5). HP и урон прежние — опаснее и тяжелее становятся только способности боссов, правило на каждый вид в `harderBy`: броня/ярость/панцирь/кровавый долг/отступление/джокер — доля больше, лечение долей от HP (регенерация, яйцо, суп) — на четверть за круг, дань/слепая зона/строгая мама/эликсир/заражение — чаще и раньше, плата/заморозка/скример/командная работа/казна/ложная смерть — дольше; флаги не меняются. Опыт за повтор ×(1 + 0.25·tier). Круг идёт до самого Кирюхи (а не «до своего этапа», как обычное перепрохождение), и его победа записывает `profile.cycle`; итоговый экран показывает «Пройдено кругов». Тест проверяет, что на последнем круге каждого босса можно победить.
- **Метка охотника, Свиток разведки, Песочные часы, Двойной удар** (`src/data/shop.ts`). Метка охотника — улучшение на 3 уровня, +15% к бонусному опыту за победу над боссом и подчинённым. Свиток разведки — улучшение в 1 уровень: в бою с боссом под его способностями видно, через сколько повторов (или пауз) сработают те, что считают повторы — яйцо, слепая зона, дань, касса, кристаллы, суп, командная работа (`src/lib/scout.ts`; пороги по HP и так отмечены на полоске). Песочные часы — расходник до 5, сами тратятся на обычный отдых (3 с → 1 с), но не на отдых перед боссом. Двойной удар — расходник до 3, включается кнопкой в бою: следующие 10 повторов по подчинённым (`doubleLeft`, по боссу не тратится) бьют вдвое; «−1» возвращает его шаг.
- **Бронебой, Зелье ярости, Оберег** (`src/data/shop.ts`, правила — в `resolveArenaRep`). Бронебой — улучшение на 3 уровня, каждый срезает «Толстокожесть» на 5% (`armorPierce`; ниже нуля броня не уходит). Зелье ярости и Оберег — расходники: покупаются по штуке (до 3 и до 2, лежат в профиле в `rage` и `wards`). Зелье пьют кнопкой под полоской HP: следующие 20 повторов арены (`rageLeft`) бьют вдвое сильнее, по любому противнику. Оберег тратится сам и только на босса: в момент, когда способность должна сработать, `ward(kind)` её гасит — лечение (Копилка, Суп, Отступление, Кровавый долг, Джокер), откат урона (Без остановки, Командная работа, Скример), заморозку Грю, Скример, Казну и Ложную смерть; один оберег — одно срабатывание, бой сообщает какое. Лечение в паузах по часам (Регенерация, Эликсир) оберег не гасит. «−1» возвращает потраченное повтором — шаг зелья и оберег (`RepUndo.itemsSpent`, разницей, а не снимком, чтобы откат повтора до выпитого зелья не выливал его).
- **Иконки способностей** (`public/abilities/<kind>.png`, `AbilityIcon`): круглые значки рядом с названием способности — в брифинге перед боем, в чипах над боссом и в карточке босса. Нарезаются из листов на белом фоне: `node scripts/slice-ability-sheet.mjs <лист> <kind> <kind> …` — виды перечисляются в порядке иконок на листе (слева направо, сверху вниз). Исходные листы — в `art/abilities/` (не в репозитории). Пока у способности нет картинки, в `ABILITY_TIPS` можно поставить эмодзи — `AbilityIcon` покажет его. С `--out shop` тот же скрипт режет иконки магазина в `public/shop/<id>.png` (`art/shop/`).
- **1 на 1** (`src/data/duel.ts`, тесты рядом; экран — внутри `RushView.tsx`): кнопка «1 на 1» под стартом Rush. Минута отжиманий против записи лучшего Rush другого игрока — его повторы по времени идут «призраком» на дорожке рядом (`GhostRace`, подписан его именем). Соперник подбирается по рейтингу: ищутся игроки с рекордом Rush в окне ±150 очков, если их меньше трёх — ±400, потом все; из пяти ближайших берётся случайный, недавних соперников «Другой соперник» пропускает. Больше повторов, чем в его записи, — победа, столько же — ничья. Без своего рекорда Rush дуэль закрыта (карточка «1 на 1» с замком): рекорд — это то, что выходит против чужого, и из него же строится спарринг-робот. С одним соперником — не больше 5 рейтинговых боёв в день (`DUEL_DAILY_LIMIT`, счёт по сопернику за день лежит в профиле в `duelDay`): кто уже набрал 5, не попадается в подборе до завтра, «Реванш» после пятого боя скрыт, а бой сверх лимита на рейтинг не идёт. Рейтинг — Эло, у всех старт 1000, K = 32; меняется только у того, кто вызвал (соперник не играл, а чужую строку писать нельзя). Если вызвать некого или не выполнен вход — «Спарринг-робот» с рекордом около твоего, без рейтинга. Дуэль — это обычный Rush: XP, рекорд и достижения засчитываются как всегда. Рейтинг и счёт побед лежат в профиле (`duelRating`, `duelWins`…), запись Rush публикуется в `players.rush_run`; в таблице лидеров вкладка «1 на 1» с очками и счётом побед–поражений. Нужны колонки: **один раз запусти `supabase/duels.sql`** в SQL Editor; до этого соперника нет — только спарринг, а у всех в таблице 1000.

- **Способности боссов** (`src/data/abilities.ts`, правила — `src/data/combat.ts`). Боссы 1–8 держат базовый ритм: Толстокожесть, Изматывание, Панцирь, Стальная воля, Ярость — всё это чистые функции текущего HP. С 9-го к базовой добавляется вторая, читающая **как именно ты тренируешься**:

  | Босс | Новая способность |
  |---|---|
  | Багровый Царь | Регенерация — каждые 3 с паузы возвращают 1,5% HP |
  | Шреддер | Слепая зона — каждый 5-й повтор проходит мимо |
  | Король | Эликсир — 10 с без удара, и он снова на полном HP (полоса эликсира) |
  | Зелёный Гоблин | Чётный урон — засчитывается каждый второй повтор |
  | Эндер-дракон | Заражение — не добил подчинённого за 15 повторов, остаток перейдёт следующему |

  **Свои способности у боссов-персонажей.** Каждому из первых восьми и Эндер-дракону к прежней способности добавлена своя — по характеру:

  Их состояние тоже живёт в `FightState` (необязательные поля `frozenLeft`, `retreatUsed`, `screamUsed`, `scream`, `crystalsBroken` — у старых сохранений их нет, это читается как «ещё ничего не было»), поэтому «−1» отменяет и их. Разовые моменты повтор отдаёт списком `events` (`AbilityEvent`), экран боя показывает самый важный штампом (`AbilityFx.tsx`). Тест прогоняет каждого из 15 боссов ровным темпом до победы — чтобы ни одна комбинация способностей не сделала бой непроходимым.

  **Разведка** (`BossBriefing.tsx`). Чтобы правила боя с боссом были известны до первого подхода против него, когда падает третий подчинённый и босс отыграл свой выход — заставку «BOSS» и реплику, — всплывает досье на него (у босса без реплики — сразу после заставки): картинка, кто идёт перед ним и все способности — у каждой иконка, что делает и строка «Как бить» (`ABILITY_TIPS` в `abilities.ts`). Всплывает каждый раз, когда падает третий подчинённый, — неважно, побеждал ли ты этого босса раньше, в том числе при перепрохождении. Если оказался на боссе другим путём (перезапуск, прыжок из дев-панели), всплывает само один раз на босса (запоминается в `arena.briefed.v2`). Счёт камеры под ним не останавливается. Открыть снова — кнопка «Этап N / 15 · разведка» на карточке этапа.

  **Перепрохождение.** Побеждённого босса можно пройти снова: на главном экране нажать на него в списке боссов → «Пройти снова». Этап начинается заново с первого подчинённого, потом босс — и дальше по порядку следующие этапы, их подчинённые и боссы (уже побеждённый босс, упав снова, отправляет на следующий этап — `bossRebeaten` в `resolveArenaRep`; список побед не меняется, бонуса за победу нет, повторы идут в общий счёт и дают обычный XP). Настоящий прогресс откладывается в `profile.replay.returnTo` и возвращается как был — тот же подчинённый, то же HP, — когда перепрохождение доходит до этапа, на котором ты остановился («Ты догнал свой прогресс»), или по кнопке «Выйти» на плашке «Перепрохождение» вверху экрана боя. «−1» откатывает и это (`RepUndo.replayBefore`). Пока идёт одно перепрохождение, второе не начать.

  Разведка всегда ждёт, пока босс договорит свою реплику, какой бы длинной она ни была, и всплывает через полсекунды после её конца.

  **Пауза в игре одна — 3 секунды** (`SET_BREAK_MS`): от неё заканчивается подход в бою и в ранге силы, и по ней же считают все способности — «Без остановки», заморозка Грю, «Строгая мама», «Скример», кристаллы, «Командная работа», «Кровавый долг», «Ложная смерть», такт «Регенерации». Подходом считается непрерывная серия с паузами короче 3 секунд. Эффекты конца подхода (Кровавый долг, Без остановки) досчитываются в начале следующего повтора — пока ты отдыхаешь, код не выполняется.

  **Регенерация — исключение: она идёт по часам.** Пока ты лежишь и дышишь, экран каждую секунду опрашивает `applyIdleRegen`, и раз в 3 секунды босс забирает свои 1,5% обратно у тебя на глазах. Считается это не «сколько раз мы успели посмотреть», а сколько целых интервалов прошло с отметки `regenAt`, — поэтому вызов раз в секунду и вызов раз в час дают одинаковый результат, и вернувшись через сутки ты найдёшь босса на полном HP, но не выше.

  Это сломало прежний принцип «способность — функция от HP», на котором держалась точность кнопки «−1». Решение: всё состояние боя вынесено в один маленький объект `FightState`, и отмена **восстанавливает его снимок**, а не пытается прокрутить каждое правило назад. Обратить «урон подхода обнулён паузой» по шагам нельзя, а снимок — точен по построению.

  Бой живёт в `combat.ts` отдельно от React и IndexedDB и покрыт тестами на синтетических часах: `npm test` проверяет каждую способность и то, что боссы без них ведут себя как раньше. Без этого баг вида «босс тихо лечится бесконечно» ловился бы только вручную.
- **Имена боссов склоняются**: «подчинённый Мясника», «подчинённый Утробы». Формы прописаны в данных (`nameGenitive`), а не выводятся правилами — русское склонение здесь нерегулярно: у «Громовержца» выпадает беглая е, «Утроба» и «Погибель» берут разные окончания.
- **Голос объявляет босса**: когда падает третий подчинённый и выходит сам босс, диктор произносит «Boss» на минимальной высоте, какую допускает синтез речи, и вдвое медленнее обычного.

  Подложка под ним **намеренно без тона**: широкополосный шум под низкочастотным фильтром, который сжимается с 380 до 60 Гц, плюс синус на 64→30 Гц — почти без обертонов, так что он скорее ощущается, чем слышится. Первая версия складывала две пилы в тритон, рассчитывая на «дьявольский интервал», но любые выдержанные осцилляторы ухо слышит как **ноты**: две сразу — это аккорд, а аккорд с мягкой атакой неотличим от нажатых клавиш пианино. У шума нет основного тона, цепляться не за что — он читается как давление, а сжимающийся фильтр даёт ощущение подступающего.

  **На повтор звучит ровно один сигнал**, выбранный по значимости события: выход на босса → победа → новый уровень → обычный повтор. Раньше добивающий повтор играл бип, фанфару и колокольчик уровня одновременно — три звука на одно событие читаются просто как шум.

  Весь звук идёт через один компрессор-лимитер: низы складываются быстро, и без него бас клиппит в дребезг, что читается как «сломалось», а не как «страшно».
- **Повтор, не нанёсший урона, объясняет себя** прямо на экране: «СЛЕПАЯ ЗОНА», «НЕ В СЧЁТ», «НЕ УМИРАЕТ!». Молча съеденный повтор выглядел бы сломанным счётчиком.
- **Карта этапа** (`StagePath`): три подчинённых и корона босса в ряд, пройденные с галочкой, текущий подсвечен. Полоса HP говорит только про того, кто перед тобой, и ничего — про то, сколько осталось до босса.
- **Галерея арены**: на главной сеткой выложены боссы всех 15 этапов — уже побеждённые, текущий и те, до кого ты ещё не дошёл. Скрывать будущих силуэтами не стали: полный ростер и есть смысл экрана, а рядом видно, как силуэт набирает массу от первого к последнему.
- **Имена и фразы** боссов свободно меняются, а вот `id` — нет: по ним в профиле хранится список побеждённых, и переименование ключа молча стёрло бы все победы. Поэтому идентификаторы внутри давно разошлись с именами (`apex` — это «Зелёный Гоблин»), и файлы иконок названы по ним же.
- **Карточка босса**: тап по любому боссу — на плитке в галерее или на строке «текущий босс» — открывает его во весь экран: крупная фигура, коронная фраза, HP и шанс крита, и сколько отжиманий до победы. Закрывается по фону, крестику или Escape.
- **Иконки боссов** — сгенерированные арты в `public/bosses/`, по одному на противника. Импортируются из папки с исходниками:

  ```bash
  node scripts/import-boss-icons.mjs ~/Downloads
  ```

  Исходники приходят названными по-русски, с подписью («1. Оскал»), вжатой в нижнюю часть картинки, и с разным количеством чёрных полей. Срезать фиксированную долю высоты нельзя — подпись стоит где угодно между 75% и 83% в зависимости от того, насколько высокий арт. Поэтому скрипт читает пиксели: находит подпись как нижний блок содержимого, отделённый от арта полосой чёрных строк (и отличает её по тому, что текст серый, а арт цветной), отрезает, а затем кадрирует квадрат по настоящему bounding box арта — чтобы все иконки были скадрированы одинаково.

  Декодирование идёт через `sips` из комплекта macOS с конвертацией в BMP, который разбирается вручную, — так в проекте не появляется ни одной зависимости для работы с картинками. На выходе JPEG: прозрачность не нужна (круг вырезает CSS), а сервис-воркер прекеширует все иконки, и JPEG весит вчетверо меньше PNG.

  Если файлов нет, `BossIcon` откатывается на процедурную SVG-фигуру `BossAvatar.tsx`, где плечи, руки, грудь и ноги интерполируются от `tier` — так свежий клон без артов рисует силуэты, а не битые картинки.
- **Speed Rush**: 60 секунд, комбо-множитель растёт при повторах чаще раза в 2 секунды, личный рекорд по числу повторов и лучшему комбо.
- **Достижения**: за общее число отжиманий, длину стрика, побеждённых боссов и рекорды Rush. Тап по плитке разворачивает под сеткой условие и статус — раньше описание жило в атрибуте `title`, то есть в подсказке по наведению, до которой с телефона не добраться.
- **Кнопка «−1»** — коррекция счёта в обоих режимах. Держит стек отмен, а не один слот: сколько повторов добавил, столько можно и снять. Откатывается всё, что дал повтор — счётчик, XP и выданные им достижения, — включая повтор, добивший босса: тот возвращается с тем HP, что был до удара, и снова считается непобеждённым. Когда откатывать нечего, кнопка гаснет.
- **Статистика** (вкладка «Статы»): сегодня, за неделю, лучший день, лучший и средний подход, темп, график по дням за 2 недели или месяц. Строится по журналу повторов — таблице `reps` в IndexedDB (`src/lib/stats.ts`, тесты рядом). Журнал только локальный: в облако синхронизируется профиль, а не история. Повторы, сделанные до появления журнала, в статистику не попадают — экран так и пишет, с какой даты ведётся история. «−1» удаляет строку из журнала вместе с повтором.
- **Карточка победы**: картинка 1080×1350 — арт босса, сколько отжиманий, критов и времени ушло на этап, ранг и дата. Рисуется на canvas (`src/lib/victoryCard.ts`) и уходит через системное «Поделиться», а на десктопе скачивается файлом. Карточка не всплывает сама: она живёт в карточке побеждённого босса — тап по нему в галерее арены на главной. Если этап начался раньше журнала, число отжиманий показывается с плюсом — это нижняя граница.
- **Заморозка стрика** (`src/lib/streak.ts`, тесты рядом): одна заморозка закрывает один пропущенный день. Новый игрок начинает с одной, ещё одна даётся за каждые 7 дней стрика, в запасе не больше двух. Тратятся они при следующем повторе после пропуска, и только если их хватает на все пропущенные дни — иначе стрик сбрасывается, а заморозки остаются. Замороженные дни к стрику не прибавляются: он по-прежнему считает дни, когда ты тренировался. Дни считаются по местному времени устройства, а не по UTC. На главной показан **текущий** стрик — сохранённое число обновляется только следующим повтором, и сломанный стрик иначе продолжал бы гореть; в таблицу лидеров уходит тоже текущий. «−1» возвращает и стрик, и потраченную заморозку.
- **Кликер**: кнопка «+» не считает отжимания — она считает нажатия. В бой, XP, стрик, «всего отжиманий», достижения, статистику и таблицу лидеров идут только повторы, засчитанные камерой; нажатия копятся отдельно в `clickerTaps` и видны на главной плиткой «Кликер» и под кнопками. «−» в ручном режиме снимает нажатие кликера (только сделанные на этом экране), в режиме камеры — последний засчитанный повтор. Прежний лимит в 20 ручных повторов со штампом «Лентяй» убран: раз нажатие ничего не даёт в игре, ограничивать его незачем.
- **Магазин** (кнопка под полосой уровня на главной, данные — `src/data/shop.ts`, тесты рядом): XP тратится на улучшения — Сила удара (+10% урона за уровень), Меткость (+2% к шансу крита), Тяжёлая рука (+0.25 к множителю крита), Второе дыхание (+1 с ко всем порогам паузы: конец подхода, «Без остановки», тик Регенерации) и заморозку стрика (в пределах прежнего лимита в 2). Платится **из того же XP, из которого считается уровень**, поэтому покупка может опустить уровень, ранг и место в таблице лидеров — это и есть цена. Покупка, которая стоит уровня, просит второе нажатие. Улучшения попадают в бой через `PlayerPerks` — необязательный аргумент `resolveArenaRep` / `applyIdleRegen`, без него бой считается как раньше. Отмена «−1» снимает снимок `FightState`, так что с улучшениями она остаётся точной.
- **Подсказки для новичков** (`src/lib/hints.ts`): на главной — карточка «Установи игру на телефон» (только в мобильном браузере, не в установленной игре; на iPhone — шаги для Safari или совет открыть страницу в Safari, на Android — кнопка «Установить» через `beforeinstallprompt`, если браузер его дал, иначе шаги через меню) и карточка «Впервые здесь?», открывающая справку **«Как играть»** — она же всегда доступна по «?» в шапке главной. На экране боя при первом входе поверх верха экрана всплывает «Как бить»: про камеру и про то, что «+» — только кликер; поверх, а не в потоке, потому что экран боя подогнан под высоту телефона. Каждая карточка закрывается крестиком и больше не показывается — отметки в `localStorage` этого устройства.
- **Анимации Rush, магазина и справки.** Rush начинается с отсчёта «3-2-1-GO!» (камера уже включена под ним, так что есть время лечь), таймер — кольцо, которое последние 10 секунд краснеет и пульсирует, каждый повтор подскакивает с «+1», карточка комбо разгорается с ростом комбо и с x5 загорается «огонь», конец — штамп «Время!» или «Рекорд!» с конфетти. В магазине карточки выезжают по очереди, покупка звучит «оплатой» (`playPurchase`: щелчок кнопки и два ярких колокольчика на кварту вверх, второй звенит дольше; плюс двойной тап вибрацией, где она есть — синтез в духе платёжного звука телефона, а не чужая запись) и даёт искры (`Burst.tsx`), «+1 ур.», заполняющееся с пружиной деление и плавно убывающий XP; если покупка стоила уровня — баланс вздрагивает, а строка уровня вспыхивает красным. В справке отжимается легионер (`PushupGuy.tsx`) без фона — только фигура: одно отжимание из ролика `art/legionary/pushup-original.mp4` (точки склейки выбраны там, где поза совпадает, поэтому повтор идёт без скачка), каждый кадр вырезан системным выделением объекта (macOS Vision) и уложен в прозрачную ленту `public/legionary/pushup.webp` — 48 кадров, листаются CSS-анимацией. Лента, а не видео: видео с прозрачным фоном браузеры поддерживают каждый по-своему, а картинка работает везде. Спящий легионер вырезан так же — `public/legionary/sleep.webp`. Разделы выезжают каскадом. Всё уважает системное «Уменьшить движение».
- **Уведомления не мешают бою** (`useToasts.ts`, `ToastStack.tsx`): компактные плашки в одну строку у верхнего края, слой не принимает касаний. На экране не больше двух; когда событий больше (удар, который убивает босса, даёт уровень и пару достижений), лишние не теряются, а встают в очередь по важности — рекорд и победа над боссом/новый уровень раньше достижений; одновременные достижения сливаются в одну плашку «Достижения: A, B». Показ короткий: 2,2 с для победы и уровня, 3 с для достижений и рекордов.
- **Призрак в Speed Rush** (`src/lib/ghost.ts`): рекордный забег хранится как моменты каждого повтора (`rushBestRun`, мс от старта, округлены до десятых — массив крошечный и уезжает в облако вместе с профилем). Во время забега под счётчиком дорожка (`GhostRace.tsx`): сверху парит призрак рекорда — полупрозрачное привидение с колышущимся подолом, моргает, ухмыляется, пока впереди, и тянет за собой шлейф тумана; снизу бежишь ты — янтарная метка с числом. Обгон — призрак рассеивается дымкой, искры и «Обогнал!», дальше он идёт потускневший и с открытым ртом; если догонит обратно — «Бу! Догнал». Рядом подпись «впереди на N / отстаёшь на N». Рекорд замораживается на старте, чтобы обгон посреди забега не сдвигал цель. Рекорды, поставленные до призраков, идут ровным темпом.
- **Календарь** во вкладке «Статы» (`Heatmap.tsx`, `heatmapWeeks` в `stats.ts`): дни квадратиками по неделям, понедельник сверху, пять оттенков янтарного от пустого до самого активного дня. На телефоне последние 20 недель, на широком экране — год. Тап по дню показывает число.
- **Цель недели** (`src/lib/weekly.ts`, карточка `WeeklyGoal.tsx` на главной): два концентрических кольца — снаружи неделя, внутри сегодня. Дневная норма (`dailyTarget`) — сколько нужно делать каждый день до воскресенья, чтобы закрыть неделю: остаток цели делится на оставшиеся дни с сегодняшним, так что перебор в начале недели её уменьшает, а пропуск — увеличивает; если неделя уже закрыта, норма — седьмая часть цели. Норму можно задать и самому — в редакторе цели поле «День» (от 1 до 1000; пусто или кнопка «авто» — снова автоматически, `dailyGoal` в профиле). Отдельной награды за день нет. Неделя — отжимания с понедельника по воскресенье против цели, которую игрок вводит сам (от 10 до 5000; 70 / 150 / 300 / 500 — быстрые кнопки, по умолчанию 150), кольцо прогресса. Повтор, на котором цель достигнута, приносит `цель × 2` XP — один раз за неделю (`weeklyRewardWeek`); «−1» снимает и награду. Считается по журналу повторов, поэтому, как и статистика, привязана к устройству.
- **Анимации интро** (`Intro.tsx`). В первом акте — ночной Колизей (фото `public/intro/colosseum.jpg`, верх и низ растворяются в темноте): из пяти прожекторов на крыше бьют лучи и качаются по небу, лампы пульсируют и время от времени вспыхивают звездой, на трибунах срабатывают фотовспышки, а крупное «PUSH UP / LEGENDS» собирается над ним по буквам из размытия. Во втором акте — тот же Колизей, только затемнённый и чуть размытый, едва видный; через секунду по центру в полный рост появляется римлянин-ведущий Кирюха (вырезан из фото системным выделением объекта — `public/intro/host-full.webp`, оригинал в `art/intro/`), поднимаясь снизу в тёплое свечение, с табличкой имени у ног. Дальше знакомство, каждая мысль — своим пузырём: сначала печатается «Привет, воин! Я создатель этого всего и хочу посвятить тебя в своё творение!», висит полторы секунды (тап — сразу дальше), затем его сменяет новый пузырь «Давай сначала познакомимся. Меня зовут Кирюха, а тебя?», и он плавно меняет позу — машет → протягивает руку (`host-greet.webp`). Затем поле «Твой ник» (2–24 символа, как имя в таблице лидеров), «Приятно познакомиться, {ник}! А сколько тебе лет?» и поле возраста (5–100), финальная фраза и кнопка «На арену». Тап по экрану допечатывает текущую фразу. Ник и возраст сохраняются в профиль (`nickname`, `age` — уходят в облачное сохранение) и в `arena.introAbout` (`src/lib/intro.ts`); ник сразу подставляется в поле «Имя в таблице» при регистрации. «Пропустить» — в правом верхнем углу. Реплики печатаются по буквам (`Typewriter`; тап допечатывает строку, следующий — листает), говорящий в это время слегка покачивается, на «Поздно. Ты уже здесь.» пузырь вздрагивает, по кнопке выхода пробегает блик, а нажатие на неё раскрывает «ворота»; свечение — светящиеся буквы названия, ореолы у факелов, «дышащий» песок арены, тёплая дымка за тем, кто говорит, сильнее подсвеченный говорящий, мягко светящийся пузырь ведущего и пульсирующие кнопки «Конечно» и «На арену». Печатающийся текст наложен на невидимую полную реплику в одной ячейке сетки — абсолютное наложение внутри строчного элемента на длинной реплике сжималось в колонку по слову в строке — свет разливается из кнопки на весь экран и переходит в игру. Переход идёт по таймеру, а не по окончанию анимации: в фоне анимации останавливаются, и вход в игру не должен от них зависеть. Отражение левого портрета задано через `scaleX` framer, иначе покачивание перезаписало бы CSS-трансформ и развернуло бы его обратно. Всё уважает «Уменьшить движение» — там текст появляется сразу, а переход мгновенный.

## Админ-панель

Правка чужого прогресса прямо из игры: дев-панель → «Админ» → «Игроки и их прогресс». Список игроков с поиском; у выбранного можно поменять отжимания, XP или уровень, стрик (станет живым на сегодня), заморозки, рекорд Rush, кликер и сбросить улучшения магазина.

**Как включить (один раз):**

1. Supabase → SQL Editor → вставить `supabase/admin.sql` → Run. Это создаёт таблицу `admins` и правила, по которым чужие сохранения можно читать и менять **только** админам. Защита — в базе: спрятанный раздел в игре — удобство, а не замок.
2. Там же сделать себя админом, подставив почту своего игрового аккаунта:

   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'твоя@почта.ru'
   on conflict do nothing;
   ```

3. Войти в игре этим аккаунтом — в дев-панели появится раздел «Админ».

**Как правка доходит до игрока.** Панель меняет облачное сохранение (`saves`) и сразу строку в таблице лидеров (`players`). Главная копия прогресса живёт на телефоне игрока; он принимает облачную версию при следующей синхронизации — примерно через 15 секунд, если игра открыта, иначе при запуске. Чтобы телефон заметил даже правку полей вне «отпечатка» прогресса (заморозки, улучшения, кликер), панель ставит в сохранение метку `adminRev`, которая входит в отпечаток (`syncMark.ts`); у сохранений, которые никто не правил, отпечаток прежний. Если игрок успел позаниматься офлайн, игра спросит его, какую версию оставить. Журнал повторов (статистика, календарь, цель недели) живёт на устройстве, правкой не меняется. Игроков без аккаунта правка не касается — их данных в облаке нет.
